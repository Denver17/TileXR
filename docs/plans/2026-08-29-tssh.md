# tssh Implementation Plan

## Goal and Scope

Implement the approved native-Windows `tssh` command described in
`docs/specs/2026-08-29-tssh-design.md`. The tool broadcasts a one-shot command
or stdin-backed Bash program to a JSON-configured cluster through Windows
OpenSSH, with bounded concurrency and complete per-host results.

The work is limited to `tools/tssh`, focused tests, `AGENTS.md`, and the design
and plan documents. It does not add scheduling, file-copy, package-management,
or NPU-workload behavior.

## Task 1: Configuration and CLI Contract

**Objective and role:** Establish the stable user interface and example
inventory consumed by later execution code.

**Background and prerequisites:** Follow `AGENTS.md` and the approved design.
Use Python standard-library conventions already present in `tools/`. Paramiko
is optional and isolated to one-time public-key setup.

**Modification scope:** `tools/tssh/clusters.json`, `tools/tssh/tssh.py`, and
focused tests under `tests/tools/tssh`.

**Constraints and non-goals:** Preserve configuration order, validate schema
version and uniqueness, expose only `tssh`, accept jobs from 1 through 64, and
do not depend on `parallel-ssh`. Normal command execution must not import or
depend on Paramiko.

**Acceptance and verification:** Parser/configuration tests demonstrate all
three example clusters, stable ordering, case-insensitive lookup, invalid
schema failures, concurrency bounds, and remote command quoting.

**Artifacts and interfaces:** A versioned JSON schema and callable Python
functions that return typed cluster, host, options, and command data.

## Task 2: Concurrent OpenSSH Execution

**Objective and role:** Implement reliable one-command-per-host dispatch and
stdin broadcasting while retaining per-host evidence.

**Background and prerequisites:** Task 1 interfaces and Windows OpenSSH are
available. The approved safety options and timeout boundary are mandatory.

**Modification scope:** `tools/tssh/tssh.py`, `tools/tssh/tssh.cmd`, and focused
tests under `tests/tools/tssh`.

**Constraints and non-goals:** Use a bounded thread pool and `ssh.exe`; do not
write command or stdin content to temporary files; close stdin unless `-I` is
selected; attempt every configured host; print results in configuration order;
return nonzero for any host failure. A local timeout must not be described as
guaranteed remote termination.

**Acceptance and verification:** Unit/component tests cover exact stdin bytes,
disabled stdin, success, remote nonzero status, launch failure, timeout,
ordering, aggregate status, and Windows launcher operation using a controlled
fake SSH process. A live read-only `hostname` run succeeds on configured hosts.

**Artifacts and interfaces:** `tools/tssh/tssh.cmd` is the only public launcher;
`tssh.py` remains directly testable. `--install-key` uses optional Paramiko and
a hidden password prompt to install the local public key without persisting the
password.

## Task 3: Benchmark and Default Selection

**Objective and role:** Choose the default concurrency from real C02-A04,
C02-A07, and C02-A09 SSH startup behavior.

**Background and prerequisites:** Tasks 1 and 2 pass focused tests and all 24
hosts complete a read-only identity command.

**Modification scope:** Benchmark evidence under `tools/tssh`, the default jobs
constant in `tssh.py`, and benchmark assertions/tests where useful.

**Constraints and non-goals:** Measure configured levels 1, 2, 4, 8, 16, 24,
32, and 64 in randomized order, one warm-up and at least five measured runs per
level. Use bounded read-only remote commands. Report 32 and 64 as effective 24,
not true 32-way or 64-way results. Default to full host concurrency with a hard
64-host cap; `-j` is an explicit limiter.

**Acceptance and verification:** The benchmark record contains configured and
effective concurrency plus median, minimum, and maximum elapsed time. Re-run a
24-host command with the selected default and confirm all per-host exits are
zero.

**Artifacts and interfaces:** A concise maintained Markdown benchmark section
or document and a tested default of 64, interpreted as all configured hosts up
to the cap.

## Task 4: Documentation, Simplification, and Final Verification

**Objective and role:** Make the tool easy for agents to invoke without
recreating orchestration scripts and ensure the final diff is maintainable.

**Background and prerequisites:** Tasks 1 through 3 are complete with current
evidence.

**Modification scope:** `tools/tssh/README.md`, `AGENTS.md`, and task-owned code
or tests when simplification/review identifies an issue.

**Constraints and non-goals:** Documentation must lead with short `tssh`
commands and stdin broadcast, not Python API examples. Record security,
timeout, benchmark, and validation boundaries. Leave unrelated repository
files untouched.

**Acceptance and verification:** Run focused tests, launcher help, short-command
live validation, stdin live validation, selected-default 24-host validation,
`git diff --check`, and inspect the final task-owned diff. Apply the code
simplification and verification-before-completion workflows after final edits.

**Artifacts and interfaces:** Complete implementation and documentation on the
`codex/tssh` worktree branch, ready for scoped Git delivery without changing
the original dirty workspace.
